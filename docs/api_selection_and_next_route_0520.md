# 数字值班员 API 比选与下一步技术路线（0520）

## 一、是否可以整合当前内容做 API 选型
可以。当前 `vhf-agent-0511` 已经具备：
- 音频上传与留档
- VAD / 预处理 / 风险规则链路
- 点验任务模拟与 AIS 目标列表
- WebSocket 事件推送

在此基础上，可以把不同厂商 API 作为 **ASR 引擎层** 的可替换候选，并保持后面的风险判断、自动回复、点验通知与前端展示不变。建议做法是：

```text
音频输入
-> 统一预处理
-> 多 ASR API 并行评测 / 主链单选
-> 风险分类
-> 自动回复 / 人工建议 / TTS / 留档
```

## 二、推荐的分层选型

### 1. 主 ASR 候选
- Qwen ASR：适合中文海事通话主链；支持 26 语言、词级时间戳、情绪检测、上下文偏置。
- OpenAI `gpt-4o-transcribe`：适合作为高质量对照组；也可测试 diarize。
- Volcengine Seed-ASR：适合长录音快速转写与批量对比。

### 2. 辅助理解候选
- Gemini Audio：更适合作为音频理解与模糊风险辅助判断，不建议直接当唯一主 ASR。

## 三、比赛版主链建议
- 主链：Qwen ASR 或 OpenAI `gpt-4o-transcribe`
- 高危辅助：LLM 根据 ASR 结果给出人工处置建议
- 自动回复：只对 `dynamic -> static` 的常规汇报开放
- 点验通知：AIS 过滤 + 模板生成 + TTS

## 四、下一步技术路线安排

### 第 1 步：ASR 比选
- 选 30~50 条代表性片段
- 并行跑 Qwen / Seed-ASR / OpenAI / Gemini
- 重点比较：船名、呼号、泊位、锚地、危险词、多人混合场景稳定性

### 第 2 步：主链固化
- 选定 1 个主 ASR
- 把其余 API 留作对照或兜底

### 第 3 步：高危与自动回复规则固化
- 高危：冒烟、着火、进水、碰撞、失控等优先拦截
- 自动回复：靠泊、抛锚、靠港等由动到静业务
- 其余进入人工建议

### 第 4 步：点验任务实装
- 海图框选 / 过线
- AIS 特征过滤：吨位、吃水、位置
- 模板生成通知
- TTS 一键播报

### 第 5 步：比赛演示
- 数字值班员大屏
- 汇报索引与留档
- API 比选卡片
- 高危人工接管 / 自动回复 / 点验通知三条闭环
