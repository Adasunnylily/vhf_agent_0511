# A/B Line Route and Low-Labor Annotation Plan

## 1. A线：后天汇报优先

目标不是证明模型已经最优，而是让甲方看到完整闭环：

```text
现场/上传音频 -> 实时转写 -> 高危拦截 -> 自动回复/人工建议 -> TTS播报 -> 点验通知
```

当前还差的汇报项：

| 模块 | 当前状态 | 后天前验收标准 |
| --- | --- | --- |
| 音频处置 | 上传识别、WebSocket结果渲染、业务仿真入口 | 能演示高危、自动回复、人工建议三条分流 |
| 流式交互 | 已有模拟流式/真流式模块，但真实低延迟还需压测 | 页面能看到逐段文本和第一条告警，不追求最终模型最优 |
| 点验通知 | 支持模拟船、框选/过线、船型/吃水/吨位筛选、TTS | 能框选命中船舶，并可视化通知文本 |
| 模型效果 | ASR仍会错船名/地名 | 用“强API预标 + 热词/知识库修正路线”解释下一步 |
| 数据闭环 | 已有预标和评测脚本 | 产出一个CSV样例、一个进度统计JSON、一个后续评测路线 |

后天前建议顺序：

1. 固定演示版本：使用 `rollback-0521-1620` 分支或汇报分支，不再频繁切换大模型链路。
2. 准备3个演示场景：`由动转静自动回复`、`离泊/其他业务人工建议`、`冒烟/着火高危拦截`。
3. 准备1个点验场景：框选北仑港区附近船舶，筛选大吃水/大吨位/指定船型，生成通知并TTS。
4. 准备1页“效果不足但可工程化优化”的说明：船名/地名错识别、压盖噪声、流式延迟，用B线解决。

## 2. B线：可泛化效果提升路线

不要把优化路线做成“堆热词”。更稳的泛化路线是三层：

| 层级 | 作用 | 输入 | 产出 |
| --- | --- | --- | --- |
| 候选生成 | 从ASR错文本中召回可能船名/地名 | 船名库、地名库、AIS当前目标、港区POI | top-k候选 |
| 上下文约束 | 用港区、航道、AIS态势约束候选 | 时间、频道、经纬度、船型、航向、泊位 | 更可信实体 |
| 语义校验 | LLM只在候选范围内选择或保留不确定 | ASR文本 + top-k候选 + 业务动作 | 修正后的结构化字段 |

推荐工程策略：

```text
ASR原文
-> 船名/地名候选召回
-> 业务动作识别
-> AIS/港区上下文约束
-> LLM结构化选择
-> 低置信度转人工
```

这条路线能解释为什么“锦龙008/锦华662”这类错误不只靠ASR解决，而是靠“语音 + 港区知识 + AIS候选”共同收敛。

## 3. 低人力标注方案

可以先用强ASR API跑全量，再人工修正。这是当前最现实的办法。

不要一开始要求人工逐字转写全部1200条。标注分三档：

| 档位 | 标注对象 | 人工要做什么 | 用途 |
| --- | --- | --- | --- |
| L0 全量预标 | 1200条全部音频 | 强ASR自动转写、规则预分类 | 建索引、找类别分布、找疑难样本 |
| L1 轻标注 | 300条左右 | 修 `primary_label_gt`、船名、地名、是否可自动回复 | 分类/抽取评测 |
| L2 精标注 | 80-100条 | 修准确文本、关键时间点、风险等级 | ASR/流式/高危召回评测 |

混合业务音频的标注粒度：

```text
原始音频 audio_id
-> conversation_segment：一段完整业务对话
-> utterance_span：一句或一次呼叫
```

汇报前先用 `conversation_segment`，不要追求纯净单句。后续为了流式性能和角色识别，再补少量 `utterance_span`。

## 4. 高危数据不足怎么办

真实高危少是正常的，不能等真实样本齐了再做。

建议三类数据并行：

| 类型 | 来源 | 用途 |
| --- | --- | --- |
| 真实高危 | 后续持续收集 | 最终验收 |
| 半合成高危 | 真实VHF背景噪声 + 人工录制/合成高危话术 | 高危召回和延迟压测 |
| 规则改写高危 | 常规句式改写成冒烟、失火、故障、人员落水等 | LLM分类稳定性测试 |

高危评测指标不看总体准确率，优先看：

```text
高危召回率 >= 95%
误报率可控
首次高危触发延迟
人工复核兜底率
```

## 5. 流式性能集怎么标

流式性能集不是逐字标注为主，而是标时间点：

| 字段 | 含义 |
| --- | --- |
| `audio_start_ms` | 音频开始 |
| `speech_start_ms` | 第一段有效语音开始 |
| `first_keyword_gt_ms` | 人耳首次听到关键风险词/业务词 |
| `first_text_ts` | 系统首次吐字时间 |
| `risk_trigger_ts` | 系统首次告警时间 |
| `final_ts` | 最终文本完成时间 |

核心指标：

```text
TTFT = first_text_ts - audio_start_ts
高危触发延迟 = risk_trigger_ts - first_keyword_gt_ms
最终延迟 = final_ts - speech_end_ts
失败率 = 无结果/断连/接口错误比例
```

## 6. 可直接运行的命令

强ASR先跑全量预标：

```bash
python3 scripts/bootstrap_asr_labels.py \
  --audio-dir /path/to/audio \
  --out data/asr_prelabeled_review.csv \
  --limit 1200 \
  --source-mode upload_audio
```

生成流式性能标注表：

```bash
python3 scripts/build_stream_perf_template.py \
  --audio-dir /path/to/audio \
  --out data/stream_perf_review.csv \
  --limit 100
```

统计标注进度：

```bash
python3 scripts/summarize_annotation_progress.py \
  --csv data/asr_prelabeled_review.csv \
  --out data/annotation_progress_summary.json
```
