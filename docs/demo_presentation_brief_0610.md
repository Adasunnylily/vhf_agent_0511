# VHF 海事交管智能体汇报简版（0610）

## 1. 明天汇报主线

一句话定位：

系统不是简单把 VHF 音频送进 ASR，而是做一个“数字值班员”：持续监听 VHF，自动听写、识别业务意图、结合规则和 AIS 态势分流，最后给出自动回复、人工审核或高危报警。

主流程：

```text
VHF语音接入
→ ASR听写
→ 船名/地名/AIS实体修正
→ 风险研判
→ 自动回复 / 人工接管 / 高危报警
→ TTS播报
→ 事件归档与人工复核沉淀
```

汇报时建议强调三点：

1. 人机协同：高危和低置信度不自动处置，优先提醒值班员。
2. 业务分流：动到静可自动回复候选，静到动必须人工审核，船船沟通默认记录但异常介入。
3. 数据闭环：人工修改 ASR、意图、船名、AIS 关联和话术会进入事件中心，作为后续优化数据。

## 4. AIS 汇报口径

当前 AIS 数据是原始多类型消息流，不是标准船舶表。已经能做三件事：

1. 从 `5/24` 静态消息里提取船名、呼号、船型等信息。
2. 从 `1/2/3/18/19/27` 动态消息里提取位置、航速、航向。
3. 转成系统可导入的 `ais_today_import.csv`，用于船名修正和风险研判。

本次遇到的问题：

```text
static_name_mmsi=19032
position_ships=708
named_ships=0
```

解释：

这说明原始数据中确实有大量船名，但当前只转换单个小时文件时，北仑 bbox 内有位置的 708 艘船没有在同一小时静态消息中出现船名。处理方式是用全天多个小时 AIS 文件一起合并，跨小时把静态船名和动态位置按 MMSI 对齐。

推荐命令：

```bash
cd /root/autodl-tmp/original/autodl-tmp/vhf_agent_0511

python3 scripts/convert_raw_ais_log.py \
  /root/autodl-tmp/original/autodl-tmp/try0505/vhf-agent/ais_data.2026-05-08_*.log.gz \
  --out data/ais_today_import.csv \
  --bbox 121.6,29.6,122.4,30.2
```

导入系统：

```bash
curl -X POST http://127.0.0.1:8000/api/ais/ships/import \
  -F "file=@data/ais_today_import.csv"
```

## 5. AIS 增强 ASR 和风险判断

AIS 对 ASR 的价值：

1. 船名纠错：语音识别出“警花662”时，在当前水域 AIS 候选中寻找近似船名，修正为“锦华662”一类真实船名。
2. 船舶定位：语音中识别到船名或呼号后，关联对应 MMSI、位置、航速、航向。
3. 态势研判：如果语音涉及加车、减速、转向、避让、船位异常，就结合 AIS 的速度、航向、位置判断是否需要人工介入。

演示接口：

```bash
curl -X POST http://127.0.0.1:8000/api/ais/analyze \
  -H "Content-Type: application/json" \
  -d '{"text":"锦华662，你能不能加点车，你现在才四节多。"}'
```

期望展示：

```text
语音涉及航速调整
已关联 AIS 船舶
输出人工复核建议
```

## 6. 明天要如实说明的边界

1. 当前麦克风链路是准实时演示，不是最终生产级原生流式 ASR。
2. 当前高危样本主要来自规则候选，真实高危还需要甲方补充或后续采集。
3. 说话人分离目前是“对话轮次模板 + 人工复核沉淀”，后续再接专用 diarization。
4. AIS 已经能接原始数据，但船名修正效果依赖“动态位置 MMSI”和“静态船名 MMSI”是否能跨时间合并成功。
