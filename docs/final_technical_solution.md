# 海事VHF语音监测智能体技术方案

## 1. 项目概述

本项目面向港口与近岸水域的 VHF 甚高频通信值守场景，构建一个“海事数字值班员助手”。系统围绕连续 VHF 语音流，完成实时语音转写、船名地名识别与纠错、业务事件切分、风险研判、自动回复/人工接管分流、周边船舶点验、事件归档和知识库辅助问答，帮助值班员在高噪声、高并发、长时守听环境中更快发现异常、更稳地完成处置闭环。

系统定位不是单一 ASR 工具，而是面向海事交管业务的智能体工作台：

- 持续监听 VHF 语音，支持上传录音、长音频模拟守听和现场麦克风输入。
- 将连续语音转写为可阅读文本，并进行船名、地名、泊位和业务动作修正。
- 将语音片段组装为业务事件，判断常规报告、离泊/开航申请、高危险情和其他业务。
- 对高危事件触发人工接管和周边船舶点验；对常规报告生成标准回复；对审批类事件提示人工复核。
- 接入 AIS/模拟船舶态势，用船名库和船位信息辅助关联目标船。
- 建立知识库 RAG 问答，支撑值班员查询交管规则、VTS报告规则和 IMO/SOLAS/COLREG 等规范依据。

## 2. 基础数据集描述

### 2.1 VHF 原始音频数据

项目使用的核心数据来自宁波舟山港附近 VHF 基站录音，音频多为真实业务通话或模拟真实值守场景的连续音频。典型文件格式为 8 kHz、单声道、A-law/PCM WAV，符合海事 VHF 窄带语音特征。

数据特点：

- 语音质量不稳定：存在电流噪声、压盖、啸叫、背景声、口音和短促指令。
- 对话结构复杂：包括船岸通话、船船沟通、交管插话、多船连续呼叫。
- 业务密度高：长音频中多个业务事件连续出现，需要自动切分和归档。
- 专有词密集：船名、泊位、航道、水域、锚地、报告线等通用 ASR 模型容易误识别。

### 2.2 标注与评测数据

项目构建了增强版 VHF 评测集标注模板，用于人工校验模型输出和业务判断结果。标注字段覆盖：

- 音频标识：文件名、片段 ID、起止时间。
- ASR 真值：人工修正文本，支持不确定文本标记。
- 业务类型：常规报告、离泊/开航申请、高危险情、其他业务、无效噪声。
- 实体字段：船名、地名、泊位、航道、锚地、报告线等。
- 风险与处置：风险等级、是否需人工、是否可自动回复、建议动作。
- 流式性能：首字延迟、最终延迟、失败率、事件闭合时间。

对于标注文档中以斜杠表示的不确定内容，评测时不纳入严格字符错误率计算，避免用不确定文本惩罚模型。

### 2.3 船名与地名领域词库

项目整理了宁波舟山港相关船名、码头、泊位、水域和业务热词，形成领域实体库和热词库。

船名规律：

- 中文船名以 4-5 字为主。
- 大量船名包含数字，用于区分同系列船舶。
- 常见前缀包括“甬港”“锦华”“锦龙”“远扬”“江丰”等。
- 同音误识别明显，例如“警花662”应归一为“锦华662”。

地名与水域包括：

- 北仑、穿山、大榭、金塘、梅山、马峙、野鸭山、黄牛礁等水域。
- 金塘水道、螺头水道、报告线、警戒区、分隔带等通航区域。
- 北仑山、海螺水泥码头、算山泊位、三期码头、四期码头等港区设施。

用途：

- ASR 后处理纠错。
- LLM 对话轮次重建。
- AIS 船名匹配与可信关联。
- 热词同步到支持热词的 ASR 模型。

### 2.4 AIS 与模拟船舶数据

系统支持两类船舶态势数据：

- 真实 AIS 原始日志：包括 MMSI、经纬度、航速、航向、时间戳，以及 5/24 类静态船名信息。
- 模拟 AIS 船舶：用于演示和点验功能，包含船名、MMSI、经纬度、船型、吃水、吨位、航速、航向、目的港等字段。

当前演示优先使用有限数量的具名模拟船舶，避免大量无名 MMSI 干扰界面。系统不允许将 ASR 疑似船名直接虚假绑定到地图，只有命中受控船名库或 AIS 可信目标时才显示关联。

### 2.5 知识库数据

知识库内置和支持导入以下资料：

- VTS 标准通信用语。
- 船舶报告规则，包括进港、抵港、开航、离港、过桥、事故、异常情况和活动报告。
- 引航报告相关规则。
- IMO/COLREG 避碰责任。
- SOLAS/GMDSS 遇险通信要求。
- 人工维护的值班经验、处置话术和规则摘要。

知识库用于 RAG 问答、处置依据解释和知识图谱展示。

## 3. 系统总体架构

系统采用 FastAPI 后端 + 单页前端原型 + 本地文件/SQLite 存储的轻量架构，便于在 AutoDL 服务器上部署演示。

```text
VHF音频 / 麦克风 / 长音频
        |
        v
音频预处理与VAD切分
        |
        v
ASR识别适配层
        |
        v
实体纠错与对话重建
        |
        v
业务事件组装
        |
        v
风险研判与LLM决策
        |
        +------------------+
        |                  |
        v                  v
AIS船位关联          知识库RAG问答
        |                  |
        +--------+---------+
                 v
        处置动作生成
                 |
                 v
自动回复 / 人工接管 / 周边点验 / TTS播报 / 事件归档
```

### 3.1 后端服务层

后端基于 FastAPI，核心模块包括：

- `app/api.py`：提供音频上传、流式任务、麦克风输入、点验、事件、知识库和 TTS 接口。
- `app/main.py`：装配 ASR、VAD、风险引擎、知识库、事件仓库和 WebSocket。
- `app/services/asr.py`：封装 Qwen、Paraformer、FunASR 等 ASR 调用。
- `app/services/preprocess.py`：统一音频格式与可选降噪。
- `app/services/vad.py`：基于能量的语音活动检测。
- `app/services/vhf_dialogue.py`：规则与 LLM 结合的对话轮次重建。
- `app/services/entity_resolver.py`：船名、地名、泊位等实体候选召回与纠错。
- `app/services/risk_engine.py`：关键词规则与 LLM 分类融合的风险判断。
- `app/services/knowledge_repository.py`：知识库检索、RAG 生成、引用和知识图谱。
- `app/services/event_repository.py`：SQLite 事件持久化。
- `app/services/demo_inspection.py`：模拟 AIS 船舶、点验筛选和广播通知。

### 3.2 前端工作台

前端为单文件原型 `ui_prototype/maritime_ai_agent.html`，面向评审和领导汇报，突出“海事值班工作台”视角：

- 左侧：实时语音流、长音频守听、现场麦克风、实时转写和船名状态。
- 中央：当前事件主控台，展示事件等级、船名、位置、原文、风险评分、处置流程和推荐动作。
- 右侧：海图态势与点验处置，展示关联船、周边船、点验半径和同步广播。
- 底部：事件队列与历史记录。
- 知识库页：RAG 对话、资料管理、检索结果和知识图谱。

### 3.3 数据存储

- 音频上传、切片和增强结果存储在本地数据目录。
- 业务事件存储到 SQLite，用于重启后查看历史归档。
- 知识库索引使用 JSON 文件维护，上传资料保存到本地知识库目录。
- 模拟 AIS 船舶和点验区域使用 JSON 文件持久化。

## 4. 技术实现说明

### 4.1 音频预处理

VHF 音频来源格式不一致，即使是 WAV，也可能存在 A-law 编码、8 kHz、双声道等情况。系统统一通过 ffmpeg 转为 ASR 需要的标准格式：

- 单声道。
- 指定采样率。
- PCM WAV。
- 可选降噪增强。

降噪链路支持高通、低通和频域降噪滤波：

```text
highpass=f=120, lowpass=f=3800, afftdn=nf=-25
```

系统支持 `off/on/compare` 三种模式，便于比较降噪前后 ASR 效果。

### 4.2 VAD 与事件切分

系统先按固定帧长计算音频能量，根据静音时长和最小语音时长切分片段：

- 高于能量阈值视为语音开始。
- 静音超过阈值视为语音结束。
- 过短片段丢弃。
- 过长片段强制截断。

VAD 切片后，系统不是把每个音频块都视为最终业务，而是按照以下层次组织：

```text
AudioFrame -> SpeechSegment -> Utterance -> BusinessEvent
```

业务事件闭合依据包括：

- 静默超时。
- 出现“收到、再会、完毕、保持守听”等结束语。
- 出现新船名且前一事件信息已足够。
- 人工手动关闭。

### 4.3 ASR 模型适配

系统将 ASR 抽象为统一适配层，支持不同模型和接口切换：

- Qwen3-ASR-Flash：作为高精度云端 ASR 演示主链路，适合上传音频和准实时分片。
- Paraformer Realtime / Paraformer Realtime 8K：作为实时识别候选，适合 8 kHz VHF 语音测试。
- FunASR / SenseVoice：作为本地或开源候选，用于后续降低延迟和提升可控性。
- 火山 Seed-ASR：用于离线选型对比，支持新版 `X-Api-App-Key + X-Api-Access-Key` 鉴权。

当前实际运行模型以 `/healthz` 输出为准。系统允许上传/长音频和麦克风使用不同 ASR 配置，便于分别优化“效果”和“延迟”。

### 4.4 船名地名实体纠错

ASR 输出后，系统通过领域词库和船舶注册表进行实体纠错：

- 召回候选船名、地名、泊位和业务动作。
- 基于字符串相似度、同音误识别、上下文和候选边距评分。
- 仅当候选分数超过阈值且边距足够时才自动关联。
- 不可靠船名显示为“待人工确认”，不生成虚假地图位置。

典型纠错：

```text
警花662 -> 锦华662
中山交管 -> 宁波舟山交管
北龙二区 -> 北仑二期
```

### 4.5 对话轮次重建

VHF 语音常包含交管短句和船方报告混合。系统采用规则 + LLM 精修的方式重建话轮：

- “请讲、收到、注意安全、再会”通常识别为交管话术。
- “谢谢老师、谢谢交管、好的好的谢谢”通常识别为船方回复。
- 船名重复出现时保持同一说话人一致。
- 无法确认时使用“待确认说话人/疑似船方A”。

LLM 精修会参考 ASR 原文、规则初修文本、领域热词、实体候选和 ASR 句子，不允许凭空新增无依据船名或地点。

### 4.6 业务分类与风险研判

系统支持规则判断和 LLM 判断融合。业务类型包括：

- `routine_report`：常规报告，如靠妥、抛妥、抵达、抛锚报告，可进入自动回复候选。
- `departure_request`：离泊、起锚、开航、穿越、解缆、备车等，需要人工审核。
- `emergency_risk`：冒烟、着火、碰撞、搁浅、失控、进水、人员落水、求救等高危险情。
- `other_business`：船船沟通、航速航向协调、普通提醒，默认持续监听和记录。
- `invalid_or_noise`：噪声、压盖、听不清或无有效业务。

风险等级包括：

- `INFO`：一般监听记录。
- `AUTO`：可自动回复候选。
- `MANUAL`：需要人工复核。
- `L1/L2/L3`：高危或异常风险等级。

处置结果包括：

- 自动回复。
- 人工复核。
- 高危接管。
- 持续监听。
- 点验与广播。

### 4.7 AIS 关联与点验

系统通过船名、MMSI、位置、时间窗口等信息进行 AIS 关联。演示阶段主要使用模拟 AIS 船舶：

- 地图仅展示具名船舶，减少无名 MMSI 干扰。
- 高危事件发生时，当前船舶高亮，周边目标按点验半径筛选。
- 支持周边船舶点验、同步广播、复制话术、人工接管、保存上报和解除告警。
- 未可靠关联 AIS 时，不生成估算位置，提示人工确认船名。

后续接入真实 AIS 接口后，可进一步引入轨迹异常判断：

- 航速异常。
- 航向突变。
- 进入限制区。
- 靠近危险水域或高危船舶。
- 与 VHF 报告位置不一致。

### 4.8 TTS 播报与事件归档

系统生成标准回复或点验通知后，可通过 TTS 播报并保存到事件记录。事件结构包含：

- 事件 ID。
- 来源类型。
- ASR 文本与修正文本。
- 业务类型和风险等级。
- 证据和建议动作。
- 广播文本。
- AIS 上下文和点验上下文。
- 复核状态。
- 创建时间。

事件进入 SQLite 后可在事件中心和底部队列中查看，支持后续人工复核与数据集沉淀。

### 4.9 知识库 RAG 与知识图谱

知识库模块采用标准 RAG 思路：

```text
问题输入 -> 文档切块 -> 关键词检索排序 -> 构造上下文 -> LLM生成回答 -> 返回引用来源和相关性
```

功能包括：

- 资料上传。
- 人工新增知识。
- 关键词检索。
- 删除知识条目。
- LLM 问答。
- 引用片段、来源、分类和相关性展示。
- 根据规则文本抽取实体关系，以节点-边形式展示知识图谱。

当 LLM API 不可用时，系统会回退到检索摘要，不影响知识库可用性。

## 5. 智能体工作流

系统围绕“感知-理解-推理-决策-行动-记忆”的智能体闭环设计。

```text
感知：持续接收 VHF 音频、AIS 船位和知识库资料
理解：ASR 转写、实体纠错、对话轮次重建
推理：业务分类、风险评分、AIS 关联、规则检索
决策：自动回复、人工复核、高危接管、持续监听
行动：TTS 播报、点验广播、保存上报、事件归档
记忆：事件库、人工复核、知识库和后续评测数据沉淀
```

典型演示流程：

1. 播放一段长 VHF 音频，模拟真实连续守听。
2. 系统实时显示转写文本。
3. 检测到高危词，如“冒烟、失控、求救”，立即切换到高危事件。
4. 中央主控台展示风险依据和推荐动作。
5. 右侧态势图高亮关联船舶和周边点验目标。
6. 值班员点击周边船舶点验或人工接管。
7. 系统生成广播话术，TTS 播报并保存事件。
8. 事件进入归档和历史记录，作为后续评测与优化数据。

## 6. 评测指标与实验方法

### 6.1 ASR 评测

核心指标：

- CER：字符错误率，用于衡量转写文本与人工真值差异。
- 船名命中率：识别并归一到正确船名的比例。
- 地名/泊位命中率：识别关键水域和码头泊位的比例。
- 空文本率：无有效识别结果的比例。
- 业务关键词召回率：如离泊、抛锚、靠妥、冒烟等关键词。

对不确定标注文本，不纳入严格 CER 计算范围。

### 6.2 流式性能评测

核心指标：

- TTFT：从语音出现到首字显示的延迟。
- Final Latency：话轮结束到最终文本返回的延迟。
- 高危触发延迟：高危语义出现到系统告警的延迟。
- 失败率：接口异常、空识别或无法归档的比例。
- 事件闭合准确率：系统切分事件与人工事件边界的一致性。

### 6.3 业务判断评测

核心指标：

- Macro-F1：各业务类型分类综合指标。
- 高危召回率：高危事件被成功识别的比例。
- 人工复核准确率：应人工审核事件是否被正确分流。
- 自动回复准确率：自动回复是否只用于常规明确业务。
- 误报率：普通业务被错误判为高危或审批的比例。

### 6.4 点验与 AIS 评测

核心指标：

- 船名-AIS 关联准确率。
- 周边点验命中率。
- 框选/半径筛选正确率。
- 未知船名误关联率。
- 点验通知闭环率。

系统部署在 AutoDL 服务器，后端和前端分离运行：

- 后端 FastAPI：`http://127.0.0.1:8000`
- 前端原型服务：`http://127.0.0.1:8766/maritime_ai_agent.html`

```bash
cd /root/autodl-tmp/original/autodl-tmp/vhf_agent_0511
mkdir -p logs
nohup bash scripts/start_autodl.sh > logs/backend.log 2>&1 &
nohup bash scripts/start_ui_prototype.sh > logs/ui.log 2>&1 &
```

健康检查：

```bash
curl http://127.0.0.1:8000/healthz
curl http://127.0.0.1:8766/maritime_ai_agent.html
```

## 8. 创新点

1. 面向连续 VHF 守听的业务事件智能体，而不是单次语音识别工具。
2. 将 ASR、实体纠错、对话轮次、风险分类、AIS 态势和知识库 RAG 串成闭环。
3. 针对海事场景构建船名、地名、泊位和业务动作领域词库。
4. 高危事件与周边船舶点验联动，形成“发现险情-通知周边-人工接管-归档”的处置链。
5. 支持人工复核结果沉淀，为后续 ASR 纠错、业务分类和知识库更新提供反馈数据。
6. 知识库问答带引用来源和相关性，并以知识图谱辅助展示规则关系。

## 9. 当前限制与后续优化

当前限制：

- 长音频事件切分仍受 ASR 延迟和 VAD 边界影响。
- 麦克风实时链路在云端 ASR 下仍存在较高延迟。
- 说话人分离主要依赖规则和 LLM 后处理，尚非端到端流式分离。
- AIS 当前以模拟数据为主演示，真实 AIS 接口仍需进一步接入。
- 高危样本数量不足，需要继续补充真实或仿真样例。

后续优化方向：

- 本地部署 Qwen3-ASR 0.6B/1.7B 或 Paraformer Streaming，降低首字延迟。
- 引入真正的 WebSocket PCM 流式 ASR 和 partial result。
- 增强 VHF 噪声鲁棒性和电流杂音降噪策略。
- 构建更标准的事件级标注集，提升事件切分和分类评测可信度。
- 接入真实 AIS 平台或批量数据源，实现轨迹异常分析。
- 将知识库扩展为带来源页码、条款编号和审核状态的正式法规库。
- 将人工复核数据回流到实体词库、热词表和 LLM few-shot 示例中，实现持续优化。

## 10. 总结

本系统围绕海事 VHF 值班业务，完成了从语音输入到事件处置的端到端原型：既能展示连续语音转写，也能结合领域实体、AIS 船位、知识库规则和风险分类完成辅助决策。系统当前已具备演示和评测基础，适合作为智能体大赛成果提交，并可在后续通过真实 AIS 接入、本地 ASR 部署和高质量标注集持续提升工程可用性。
